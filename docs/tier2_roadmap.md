# Tier 2 & Tier 3 Roadmap

> What I would build next, with a clear line between "production-ready
> for a real bank" and "pioneering research."

The MVP (Tier 1) covers a single AI-fraud vector - deepfake-driven
wire fraud - end-to-end. The platform is intentionally architected so
the next two tiers add capabilities **without rewriting the core**.

---

## Tier 2: Production-Hardened (3-6 months)

### 2.1 Streaming Feature Aggregations
Today the `FeatureComputer` recomputes per-event windows from a
in-memory history. At production scale (10K+ events/sec/account) this
is the first bottleneck.

**Replace with:**
- **DynamoDB Streams** + Lambda aggregator -> writes 1h/24h/7d rollups
  back to DynamoDB
- **Materialized views** in RDS for cross-account join
- **Flink / KDA** if cross-account velocity is required (re-evaluate
  cost vs. serverless)

**Acceptance:** p99 latency < 200ms with 50K events/sec.

### 2.2 Real Sanctions and PEP Lists
Replace `data/sanctions_list.json` with:
- **OFAC SDN** (full list, weekly updates)
- **UN 1267** + **EU CFSP** + **UK HMT**
- **Dow Jones / Refinitiv World-Check** PEP data (paid)
- **Fuzzy match** by name + DOB + country via ElasticSearch / OpenSearch

**Acceptance:** < 50ms lookup, false-positive rate < 0.5%.

### 2.3 Voice-Biometric Deepfake Detection
For high-value wires, integrate a **voice-biometric** verification step
on the instructing call:
- **Pindrop / Nuance** for liveness + voiceprint match
- **Resemble.ai / Hive** for synthetic media detection on any
  voice sample attached to the event

This pairs with the **R007 (Voice deepfake-likely voiceprint mismatch)**
rule that already exists in `configs/rules.yaml`.

### 2.4 Model Monitoring + Drift
The model is trained on synthetic labels today. In production:
- **Evidently AI** for data + concept drift
- **MLflow model registry** with stage transitions (Staging -> Production)
- **Shadow scoring**: new model runs in parallel, predictions logged,
  no impact on decisions
- **Champion/challenger A/B** for promoted candidates

**Acceptance:** Champion is shadowed for 14 days before promotion.

### 2.5 SOC2 + FS-AI RMF Compliance Package
- Audit log retention (7 years) to S3 Glacier with object lock
- Tamper-evidence via **Merkle-tree log** (e.g., immudb)
- Annual **bias audit** across demographic segments (FS-AI RMF §4.2)
- **Pen test** + red-team exercise for prompt-injection + voice cloning
- **Vendor risk assessment** for every cloud provider and model vendor

### 2.6 Cross-Bank Mule Ring Intelligence
- Federated graph (banks share hashes, not raw PII) using
  **NIGC consortium** (UK) or **FRONTIER+** (Singapore/HK)
- Privacy-preserving via **Private Set Intersection** (PSI)
- Each bank contributes accounts in flagged rings; the union
  improves detection across the network

**This is the highest-leverage Tier 2 work** - a single ring
discovered across 3 banks can save 9x the loss.

## Tier 3: Pioneering / Research (6-18 months)

### 3.1 Graph Neural Network Scorer
The current XGBoost scorer is excellent for tabular features. For
graph-aware scoring (a beneficiary 2 hops from a known mule) a GNN
adds marginal lift that pure tabular features miss.

**Plan:**
- Build the feature vector as node embeddings from Neo4j GDS
  (Node2Vec, GraphSAGE)
- Add as a third score to the hybrid ensemble
- Keep XGBoost + rules as the explainability backbone

### 3.2 Foundation-Model Reasoning Layer
For the **case detail** UI, use an LLM to summarize the evidence
chain ("Why was this blocked?") in plain English. The LLM does NOT
make the decision; it only narrates the deterministic decision.

This addresses the **FS-AI RMF Explainability** principle without
giving the LLM any decision authority.

### 3.3 Cross-Rail Federation
Extend from wires to:
- **Real-time payments** (FedNow, RTP, FPS, UPI)
- **Card rails** with merchant-category risk
- **Crypto on-ramps** (TRM / Chainalysis integration)

The interface (`EventPublisher`, `EventConsumer`) is rail-agnostic-
only the `RailType` enum and the data schema change.

### 3.4 Adversarial Robustness
Train a second model on **adversarial examples** generated by an
internal red-team. The two models form a self-defending ensemble.
Compare to:
- **Microsoft Counterfit** for adversarial input fuzzing
- **IBM Adversarial Robustness Toolbox** for model hardening

### 3.5 Privacy-Preserving Collaboration
For cross-bank mule ring detection, mature options include:
- **Fully Homomorphic Encryption** (FHE) - still slow but
  Cloudflare / Duality have demoed in banking
- **Trusted Execution Environments** (TEEs) - Intel SGX, AWS Nitro
- **Differential privacy** with calibrated noise on shared features

## What's NOT in Any Tier (and Why)

- **GNN as the primary model** - recruiter-recognizability of
  XGBoost outweighs the marginal accuracy gain
- **Blockchain for audit trail** - S3 + object lock + Merkle log
  give the same guarantees at 1/1000 the cost
- **Real-time payments with crypto settlement** - out of scope
  for fraud detection; that's the payment rail's job
- **AI agents that file SARs automatically** - the bank must own
  the SAR decision, not the model; we surface, they file
